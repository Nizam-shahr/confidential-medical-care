## 🔍 What is ConfidentialCare?

ConfidentialCare is a decentralised medical consultation platform where patients can describe symptoms to verified doctors **without ever revealing their identity**. All medical data is encrypted client-side using **Zama's Fully Homomorphic Encryption (FHE)** before it touches the blockchain — not even the network, the contract owner, or other doctors can read it.

This is not a replacement for in-person care. It is a **private first point of contact** for people who face stigma, discrimination, or legal risk when seeking medical help for sensitive conditions — HIV/AIDS, mental health, sexual health, addiction — especially in regions where such conditions carry criminal, social, or employment consequences.

---

## 🎯 The Problem

800 million people live in regions where certain health conditions are stigmatised or criminalised. Traditional telemedicine still exposes patient identity through accounts, emails, and metadata. Blockchain-based health apps store data on a public ledger anyone can read.

**FHE changes this.** With ConfidentialCare:
- The patient's complaint is encrypted in the browser using TFHE before being stored on-chain
- Only the assigned doctor can decrypt it — enforced by the Zama ACL system
- The doctor's response is encrypted back to the patient only
- No names, no emails, no real identity — just a wallet address

## ✨ Features

| Feature | Description |
|---|---|
| 🔒 FHE-encrypted complaints | Patient symptoms encrypted with `euint64[128]` chunks (1024 chars) |
| 🩺 Verified doctor registry | Admin-managed on-chain doctor list with specialties |
| 🔑 ACL-based access control | `FHE.allow()` grants decrypt permission only to the assigned doctor |
| 🔓 In-browser decryption | Doctor decrypts complaint using `userDecrypt` + EIP-712 signature |
| 💊 Encrypted doctor response | Response FHE-encrypted back — only the patient can read it |
| 📬 EtherMail notifications | Wallet-to-wallet encrypted notifications via EtherMail |
| 🔄 Re-grant access | Patient can re-grant doctor ACL if propagation fails |
| 🚫 Anonymous by design | Patient wallet is pseudonymous — doctor never sees real identity |

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                         PATIENT BROWSER                             │
│                                                                     │
│  1. Type symptoms → encryptText() → euint64[128] chunks             │
│  2. inputProof generated by Zama Relayer SDK (CDN)                  │
│  3. Encrypted chunks + proof sent to smart contract                 │
│  4. grantDoctorAccess() → FHE.allow(chunk, doctorWallet)            │
└───────────────────────┬─────────────────────────────────────────────┘
                        │  on-chain tx (Sepolia)
                        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    ConfidentialCare.sol                             │
│                                                                     │
│  - Stores euint64[128] complaint chunks (ciphertext on-chain)       │
│  - ACL: FHE.allowThis() + FHE.allow(chunk, doctorWallet)            │
│  - Zama coprocessor processes FHE operations                        │
│  - Doctor response stored as separate euint64[128] chunks           │
└───────────────────────┬─────────────────────────────────────────────┘
                        │  Zama Gateway (ACL propagation ~3-5 min)
                        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         DOCTOR BROWSER                              │
│                                                                     │
│  1. generateKeypair() → NaCl keypair                                │
│  2. createEIP712() → sign with wallet                               │
│  3. userDecrypt() → Zama relayer verifies ACL → returns plaintext   │
│  4. Doctor reads complaint, writes response                         │
│  5. Response FHE-encrypted → FHE.allow(chunk, patientWallet)        │
└─────────────────────────────────────────────────────────────────────┘
```

## 🔐 How FHE is Used

ConfidentialCare uses the **Zama Relayer SDK (v0.4.2)** loaded via CDN and the `ZamaEthereumConfig` contract base on Sepolia.

### Encryption flow (patient)
```typescript
// 1. Text → uint64 chunks (8 bytes each, up to 128 chunks = 1024 chars)
const chunks = textToUint64Chunks(symptomsText);

// 2. Create encrypted input using Zama SDK
const inputBuilder = fhevmInstance.createEncryptedInput(contractAddress, userAddress);
chunks.forEach(chunk => inputBuilder.add64(chunk));
const { handles, inputProof } = await inputBuilder.encrypt();

// 3. Submit to contract — stored as euint64[128] on-chain
await contract.submitConsultation(doctorId, handles, inputProof, chunkCount);

// 4. Grant ACL — doctor wallet can now decrypt
await contract.grantDoctorAccess(consultationId);
// → internally calls FHE.allow(chunk, doctorWallet) for each chunk
```

### Decryption flow (doctor)
```typescript
// 1. Generate ephemeral NaCl keypair
const keypair = fhevmInstance.generateKeypair();

// 2. Sign EIP-712 message proving wallet ownership
const eip712 = fhevmInstance.createEIP712(keypair.publicKey, [contractAddress], timestamp, 10);
const signature = await signer.signTypedData(eip712.domain, eip712.types, eip712.message);

// 3. Zama relayer verifies ACL and returns decrypted values
const result = await fhevmInstance.userDecrypt(
  handleContractPairs, keypair.privateKey, keypair.publicKey,
  signature, [contractAddress], signer.address, timestamp, 10
);

// 4. Reconstruct text from decrypted uint64 chunks
const text = uint64ChunksToText(Object.values(result).map(BigInt));
```

### Key functions

| Function | Role | Description |
|---|---|---|
| `addDoctor()` | Admin | Register a verified doctor wallet |
| `deactivateDoctor()` | Admin | Remove a doctor from the platform |
| `submitConsultation()` | Patient | Store FHE-encrypted complaint on-chain |
| `grantDoctorAccess()` | Patient | `FHE.allow()` complaint chunks to doctor |
| `submitResponse()` | Doctor | Store FHE-encrypted response on-chain |
| `getComplaintHandles()` | Doctor | Retrieve euint64 handles for decryption |
| `getResponseHandles()` | Patient | Retrieve response handles for decryption |
| `closeConsultation()` | Patient | Mark consultation as closed |
| `transferAdmin()` | Admin | Transfer admin role to new address |

### Data structures
```solidity
struct Consultation {
    uint256 id;
    address patient;                    // pseudonymous wallet
    uint256 doctorId;
    ConsultStatus status;               // Open | Responded | Closed
    uint256 createdAt;
    euint64[128] complaintChunks;       // FHE-encrypted symptoms
    uint8 complaintChunkCount;
    euint64[128] responseChunks;        // FHE-encrypted response
    uint8 responseChunkCount;
    bool hasResponse;
}
```

## 🚀 Local Setup

### Prerequisites
- Node.js 18+
- MetaMask or OKX Wallet browser extension
- Sepolia ETH (get from [sepoliafaucet.com](https://sepoliafaucet.com))

### 1. Clone the repository
```bash
git clone https://github.com/YOUR_USERNAME/confidentialcare.git
cd confidentialcare
```

### 2. Install dependencies
```bash
cd frontend/frontend
npm install
```

### 3. Configure environment
```bash
cp .env.example .env.local
```

Edit `.env.local`:

```bash

```

Open [http://localhost:3000](http://localhost:3000)

## 🔄 User Flows

### As a Patient
1. Connect wallet (MetaMask / OKX) on Sepolia
2. Go to **Find a Doctor** → browse by specialty
3. Click a doctor → describe symptoms (up to 256 chars)
4. Click **Encrypt & Submit** → symptoms encrypted in browser → stored on-chain
5. **Grant Doctor Access** → ACL permission sent to Zama coprocessor
6. Notify doctor via **EtherMail** (wallet-to-wallet encrypted message)
7. Wait for doctor's response → **Decrypt Response** in your browser

### As a Doctor
1. Connect registered doctor wallet on Sepolia
2. Go to **Doctor Inbox** → see assigned cases
3. Click a case → **Decrypt Complaint** → sign EIP-712 in wallet
4. Read the decrypted symptoms
5. Write medical advice → **Encrypt & Send Response**
6. Response stored on-chain, encrypted to patient wallet only

### As Admin
1. Connect deployer wallet on Sepolia
2. Go to **Admin Panel** (only visible to admin wallet)
3. **Add Doctor** → enter wallet address, name, specialty, credentials
4. **Deactivate Doctor** → remove from active list

## ⚠️ Important Notes

**ACL Propagation Delay**
After `grantDoctorAccess()` is called, the Zama coprocessor typically relays the ACL permission to the Gateway chain within **~1 minute**. During network congestion this can take up to 3-5 minutes. If the doctor sees a decryption error, wait a minute and retry. The patient can also use the **Re-grant Doctor Access** button to resubmit ACL permissions.

**FHE Initialisation**
The Zama SDK loads from CDN after wallet connection. A loading overlay appears during initialisation (~2-5 seconds). Encryption and decryption will not work until the "FHE Active" pill appears in the navigation bar.

**Network**
All transactions run on **Ethereum Sepolia testnet**. The app will prompt you to switch networks if you are on the wrong chain.
